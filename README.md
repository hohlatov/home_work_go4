# Домашние задания по Go — Gateway и Ledger

Два независимых Go-сервиса в одном репозитории, у каждого свой `go.mod`.

```
.
├── gateway/                  # HTTP-шлюз
│   ├── go.mod
│   └── main.go               # HTTP-сервер на :8080, обработчик GET /ping
└── ledger/                   # бизнес-логика
    ├── go.mod
    ├── main.go               # запуск сервиса и демонстрация сценариев
    ├── budgets.json          # бюджеты, загружаемые при запуске
    └── internal/ledger/
        ├── validation.go     # интерфейс Validatable, CheckValid, ValidationError, ошибки валидации
        ├── transaction.go    # модель Transaction и её метод Validate
        ├── budget.go         # модель Budget и её метод Validate
        ├── ledger.go         # хранилище и бизнес-логика: AddTransaction, SetBudget, ListTransactions...
        ├── loader.go         # LoadBudgets — загрузка бюджетов из JSON
        └── *_test.go         # тесты
```

Нужен Go 1.22 или новее.

## Задание 1. Gateway

```bash
cd gateway
go run .
```

В другом терминале:

```bash
curl -i http://localhost:8080/ping
```

Ожидаемый ответ:

```
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8

pong
```

Другие методы (например, `POST /ping`) получают `405 Method Not Allowed`.
Остановить сервер: `Ctrl+C`.

## Задание 2 (ДЗ 2). Транзакции в Ledger

- `Transaction` — структура с полями `ID`, `Amount`, `Category`, `Description`, `Date` (`time.Time`).
- Хранилище — срез `[]Transaction` в памяти, при запуске он пустой. Доступ защищён `sync.RWMutex`.
- `AddTransaction(tx Transaction) error` — назначает `ID = len(slice)+1` и добавляет транзакцию.
  Если дата не указана, подставляет текущее время. Проверку данных с ДЗ 4 выполняет `Transaction.Validate()`.
- `ListTransactions() []Transaction` — возвращает копию всех транзакций.

## ДЗ 3. Бюджеты и обработка ошибок в Ledger

- `Budget{Category, Limit}` — бюджет на категорию.
- Хранилище — `map[string]Budget`. Ключ — название категории в нижнем регистре без пробелов по краям,
  поэтому «Еда», «еда» и « ЕДА » считаются одной категорией.
- `SetBudget(b Budget) error` — добавляет бюджет или обновляет лимит. Проверку данных выполняет `Budget.Validate()`.
- `AddTransaction` теперь проверяет бюджет. Если для категории задан бюджет, а сумма уже сохранённых
  транзакций вместе с новой больше `Limit`, функция возвращает ошибку `budget exceeded` (`ErrBudgetExceeded`,
  её можно проверить через `errors.Is`) и **не сохраняет** транзакцию. Можно потратить ровно до лимита.
  Суммы сравниваются с точностью до копеек. Проверка и добавление выполняются под одной блокировкой.
- `LoadBudgets(r io.Reader) error` — читает JSON-массив бюджетов и применяет каждый через `SetBudget`.
  Ошибки возвращаются с понятным описанием: пустой ввод, синтаксическая ошибка с позицией, неверный тип поля,
  неизвестное поле (например, опечатка `limt`), не массив, некорректный лимит с номером элемента.
  Если хотя бы один элемент некорректен, ни один бюджет из файла не применяется.

Формат файла `ledger/budgets.json`:

```json
[
  { "category": "Транспорт", "limit": 2000 },
  { "category": "Образование", "limit": 6000 },
  { "category": "Развлечения", "limit": 1500 }
]
```

## ДЗ 4. Интерфейсы и валидация в Ledger

Проверка данных отделена от бизнес-логики: каждая модель проверяет себя сама,
а `ledger.go` отвечает только за хранение и бизнес-правила (бюджеты).

- **`Validatable`** (`validation.go`) — интерфейс с единственным методом `Validate() error`.
- **`Transaction.Validate()`** (`transaction.go`): сумма > 0 (0, отрицательные, NaN и бесконечность отклоняются),
  категория не пустая, дата указана.
- **`Budget.Validate()`** (`budget.go`): категория не пустая, лимит > 0.
- `Validate()` ничего не логирует, а только возвращает ошибку. Выводит её вызывающий код (`main`).
  Возвращается `*ValidationError` со **всеми** найденными проблемами сразу:
  ```
  некорректная транзакция: сумма должна быть больше 0 (получено -300); категория не может быть пустой; дата не указана
  ```
  Каждую проблему можно проверить через `errors.Is(err, ledger.ErrInvalidAmount)` и т. п.
- **`AddTransaction`** и **`SetBudget`** вызывают `Validate()` перед добавлением. При ошибке объект не сохраняется,
  а ошибка возвращается вызывающему коду. `LoadBudgets` проверяет через `Validate()` каждый элемент JSON.
  Валидация выполняется **до** проверки бюджета, поэтому некорректная транзакция не может дать ошибку `budget exceeded`.
- **`CheckValid(v Validatable) error`** — функция, работающая с любым типом через интерфейс.
  В `main` (раздел 4) она вызывается для `Transaction`, `Budget` и `*Budget` — это полиморфизм через интерфейс.

Логика ДЗ 3 не изменилась: все сценарии с бюджетами дают тот же результат.
Единственное намеренное изменение — отрицательная сумма транзакции теперь тоже ошибка (раньше отклонялся только 0).

## Запуск Ledger

Запускать нужно из папки `ledger`, потому что `budgets.json` открывается по относительному пути:

```bash
cd ledger
go run .                              # использует budgets.json
go run . -budgets /path/to/other.json # другой файл бюджетов
```

Что делает `main`:

1. Задаёт начальные бюджеты через `SetBudget`: Еда — 5000, Транспорт — 3000.
2. Загружает `budgets.json` через `os.Open` + `bufio.NewReader` + `LoadBudgets`. Транспорт меняется на 2000,
   добавляются Образование и Развлечения.
3. Показывает ошибки загрузки: отсутствующий файл, битый JSON, неверный тип, опечатку в поле, отрицательный лимит.
4. Вызывает `CheckValid` для корректных и некорректных транзакций и бюджетов.
5. Прогоняет сценарии добавления транзакций, в том числе с нулевой и отрицательной суммой и пустой категорией. Для каждого печатается `ПРИНЯТО` или `ОТКАЗ` с причиной,
   а `✓` означает, что результат совпал с ожидаемым.
6. Увеличивает лимит «Транспорт» через `SetBudget` до 2500 и повторяет отклонённую транзакцию, теперь успешно.
7. Выводит сохранённые транзакции и исполнение бюджетов. В конце проверяет, что отклонённых транзакций
   в списке нет.

Фрагмент ожидаемого вывода:

```

✗ ledger.Transaction   некорректная транзакция: сумма должна быть больше 0 (получено -300); категория не может быть пустой; дата не указана
✓ ledger.Budget        корректно
✗ ledger.Budget        некорректная запись бюджета: лимит должен быть больше 0 (получено 0)
```

## Тесты

```bash
cd ledger
go test -race ./...
```

Тесты покрывают: транзакцию в пределах лимита и ровно до лимита, превышение (транзакция не сохраняется),
регистр в названиях категорий, категорию без бюджета, обновление лимита, валидацию `SetBudget`,
погрешность float64, параллельное добавление, а также `LoadBudgets` на корректных и 10 видах некорректных данных.
Для ДЗ 4 добавлены табличные тесты `Transaction.Validate` и `Budget.Validate`, тесты `CheckValid` с разными типами
(значения, указатели, `nil`) и проверка того, что `AddTransaction`/`SetBudget` не сохраняют невалидные объекты.
